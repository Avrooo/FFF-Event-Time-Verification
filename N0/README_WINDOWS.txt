NAMRC N0 — FULL 100-LAYER B01 ENERGY ACCOUNTING (A0 / A2 / A6 / R2)
============================================================================
This package has ACTUAL R8.4 Rust solver source recovered from the prior N1 archive,
plus the exact adapted B01 G-code from R8.1. The Python scripts launch the actual
solver, then independently audit its recorded histories using the R8.2/R8.4
streaming energy-audit equations.

1. Prerequisites
   * Windows 10/11 and Anaconda / Jupyter, Python 3.10+, numpy, pandas optional
   * Rust installed (https://rustup.rs/) with Windows MSVC build tools.
   * Reopen Anaconda Prompt; run `cargo --version`.
   * Sufficient free disk/RAM. 0.25 K output typically ~2 GB peak during solver,
     0.1 K output can need substantially more memory and time. 16 GB+ RAM advised.
     Keep at least several GB free. If low on memory, run only 0.25 K initially.

2. Extract ZIP, open N0_Full_Print_Energy_Audit_Windows.ipynb in Jupyter,
   run cells in order. Notebook must remain beside n0_runner.py and solver/.
   The notebook uses subprocess and calls Rust/Cargo directly; no Colab.

3. CLI equivalent from the extracted folder:
      python n0_runner.py --cases A0 A2 A6 R2 --thresholds 0.25
      python n0_runner.py --cases A0 A2 A6 R2 --thresholds 0.1 --no-build
   The second call is optional if memory/disk are limited. Recommended to check
   the 0.25 K full-print results first before proceeding.

   Preparation without running:
      python n0_runner.py --cases A0 A2 A6 R2 --thresholds 0.25 --prepare-only

   If the solver already ran, re-audit without repeating the simulations:
      python n0_runner.py --cases A0 A2 A6 R2 --thresholds 0.25 --audit-only
   Delete an outdated *_audit.json when intentionally re-auditing revised outputs.

4. Results in N0_results/:
   * N0_full_print_summary.csv (one row per scenario and storage threshold)
   * N0_storage_sensitivity.csv (difference between finer and coarser thresholds)
   * A0_md0p25_audit.json etc: detailed components and clock reconstruction.
   Each raw case in N0_runs/ includes original solver outputs and run_status.json.

5. Scientific interpretation:
   A0 = corrected / M2 bed / constant 3 W m^-2 K^-1 film / no fan
   A2 = A0 + legacy deposition/cooldown timing (D1–D3 grouped)
   A6 = all legacy switches, original bed M0, original cp step, original h(z)
   R2 = A6 but corrected timing

   Keep the same 215C deposition, 60C bed, 25C *historically assumed* ambient,
   constant physical properties and 0.05 s time step as R8.4. The 23–24 C room
   temperature reported afterward is NOT substituted into this historical
   ablation, to avoid a confounded change.

   Audit uses physically elapsed time and correct thermophysical cp table for
   all four model outputs, with each model's documented bed and convection law.
   Thus a high legacy residual is a physical-clock consistency discrepancy.
   Fan is disabled in all cases, so forced-convection energy should be zero.
   Net bed energy can be negative (bed heats the part), as intended.

   'heat_in_J' is initial deposited thermal energy ABOVE AMBIENT, not mass/enthalpy
   of extruded material relative to zero kelvin. 'stored_change_J' is the change
   from initial deposited temperature to final recorded model temperature, so it
   is typically negative. Cooling and all face losses are accounted by signed
   convention. Audits are reconstructed from event-triggered outputs, so the
   residual depends on the storage dead band.

   IMPORTANT: Clock reconstruction is computed from activation times and the
   inspected R8.4 Rust source, not from an instrumented internal physical-step
   counter. It distinguishes deposition and cooldown integration exposure.
   Do not compare a 4-layer, md=0.0 audit directly to 100-layer md=0.1/0.25.

6. Known restrictions:
   * No fan physics included by design (numerical-timing isolation only).
   * Experimental FLIR validation is not established by this experiment.
   * The existing source groups legacy D1–D3 under one toggle.
   * The auditing engine presumes rectangular hexahedral cells and complete
     per-element output histories. If you change mesh divisions, rewrite checks.
   * No full-print result is included in the package: it must be generated by
     actually running the code on your Windows machine.
